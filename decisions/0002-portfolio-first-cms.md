# 0002: ポートフォリオ優先へ方針転換

- Status: Accepted
- Date: 2026-09-09

## Context（背景・制約）

- 既存サイトはサービス案内寄りの印象が強く、ポートフォリオ価値と記事発信の両立が不明瞭だった。  
- 開発者は `サービス窓口` から `作品・実績 + 記事` を見せるサイトへ移行したい。  
- 画像リンク切れ対策として `data/image-assets.json` の台帳運用をすでに導入済みで、将来の更新計画が必要。  
- 認可/API の再設計と CMS 的統合は大きいため、見た目最適化と土台整備を順序立てる必要がある。

## Decision（決定）

- サービス色を薄め、ポートフォリオを主軸に据える。  
- 既存の Markdown 編集基盤と画像台帳設計を保全しつつ、記事と作品を同一 CMS 的思想で運用する。  
- まず実装より先に `PORTFOLIO_CMS_ROADMAP.md` で工程を固定し、再設計対象と完了条件を文書化する。

## Reason（理由）

- 既存資産（layout、コンポーネント、編集 UI、画像台帳）が再利用しやすい。  
- 壊して作り直すより、既存ルートとデータフローを維持したほうがリスクが小さい。  
- 先に「作品導線」を固めると、後続の CMS/API 再設計時にも判定軸が明確になる。

## Alternatives（代案）

- 1から CMS ベースの新規実装を作る（保留）。  
- 既存構成を最小修正で広告サイト寄りに残す（目的から逆行）。  
- Works を外部 SaaS に完全委譲する（自前性と編集柔軟性が下がる）。

## Consequences（影響）

- 一部既存サービスページの文言・導線は後方互換を保ちつつも優先度低下。  
- `blog/` と `works/` の同型運用を進めるために、API・編集 UI の拡張が必要。  
- 画像台帳の運用は継続されるため、今後の本画像切替が比較的容易になる。
